Прошивка устанавливается со страницы на GitHub Pages (`https://wassili-hense.github.io/EspNode/`):
браузер прошивает ESP32 через Web Serial и записывает раздел `cfg` с настройками, выбранными по шаблону.
Одна прошивка на все устройства, учёт устройств не ведётся. Разметка flash и формат `cfg` —
[docs/cfg-format.md](docs/cfg-format.md).

## 1. Прошивка: раздел `cfg`

- [ ] `partitions.csv`: раздел `cfg` (data, 0x41) на 0x1A0000, 4 КБ; `CONFIG_ESPTOOLPY_FLASHSIZE_4MB`
  в `sdkconfig.defaults`.
- [ ] Компонент чтения `cfg`: magic, version, CRC-32, записи TLV; незнакомые записи пропускаются;
  при ошибке — значения Kconfig и сообщение в журнал.
- [ ] `main.c`: интерфейсы, имя и адрес узла — из `cfg`, Kconfig — только значения по умолчанию.
  Недопустимые пины или порт — как испорченный `cfg`. Первый интерфейс — клиент: через него узел
  подключается к своему шлюзу; следующие — шлюз (брокер) для узлов X13 на них, сообщения в FORWARD.
- [ ] По умолчанию (нет `cfg`) MQTT-SN — UART0 (TX 1, RX 3, 38400): плату достаточно подключить по USB к
  Enviriot. Консоль ESP-IDF и журнал загрузчика уводятся с UART0 (выключить или на другой UART); сообщения
  ROM при сбросе (115200) остаются — проверить, что Enviriot их переживает. UART1 освобождается для программ.
- [ ] `generation`: хранить в NVS последнее применённое; новое значение сбрасывает имя, адрес узла и
  адрес шлюза, записанные по сети, но не список объектов OD и не программу PLC.
- [ ] Тип устройства (0xFFC0) из интерфейсов, а не из Kconfig; буквы PHY как в X13: WiFi — W, RS-485 — M.
- [ ] Хостовый тест разбора `cfg` на примере из [docs/cfg-format.md](docs/cfg-format.md).

## 2. Прошивка: WiFi и MQTT-SN по UDP

- [ ] WiFi STA из `cfg`: SSID, пароль, DHCP или статический IP; `WIFI_STORAGE_RAM` — без копии пароля
  в NVS драйвера; переподключение с нарастающей паузой.
- [ ] Транспорт UDP (`mqttsn_transport_t`): порт 1883, адрес — IPv4 (4 байта, как у LAN-узлов X13
  и в `MsGUdp`); SEARCHGW — широковещательно в подсеть; запись `MQTTSN_GATEWAY` — шлюз задан явно.
- [ ] DHCP X13 (0x43/0x44) по UDP не нужен: адрес узла — его IP.

## 3. Прошивка: RS-485 X13 (шаблон «WiFi + RS-485»)

- [ ] RS-485 — второй интерфейс, то есть шлюз: узлы X13 на шине работают через этот узел, сообщения
  упаковываются в FORWARD, как у шлюзовых узлов X13 (PHY2). Enviriot FORWARD понимает (`MsForward`),
  правки там не нужны. Для своих протоколов (Modbus) программе доступны UART 1/2 (функции 21–23).
- [ ] Транспорт кадра X13 RS-485: `F0 1C LEN DST SRC DATA CRC`, 200000 бод, передача только при свободной
  шине, DE.
