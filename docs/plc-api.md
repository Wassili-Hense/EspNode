# PLC на EspNode

Программы PLC компилирует Enviriot (`plugins/MQTT_SN/DPLC`), байткод совместим с X13 (`extplc_vm.h`)
и дополнен float-командами. Ввод-вывод настраивает сама программа: функции `ConfigPin1`/`ConfigPin2`
в блоке инициализации, опкоды `IN`/`OUT` в цикле, функции шин TWI и UART. Канал — номер GPIO.

Номера функций, режимов и кодов ошибок — контракт с Enviriot (`LoadNativeFunctions` в
`DPLC/Compiler.cs`, будущий DeviceLogram, см. [enviriot-todo.md](enviriot-todo.md)).

## API функции

Опкод `0xC6 <номер>`. Аргументы компилятор кладёт на стек с последнего, функция снимает их по порядку;
все аргументы — целые. Если аргументов на стеке не хватает, программа останавливается с `0x87`, и
функция ничего не делает.

Функции TWI и UART — те же, что в X13 (имена из `LoadNativeFunctions`), шина TWI 1 — функциями 40–43.

| № | Функция | Описание |
|---|---|---|
| 1 | `void TwiControl(ctrl)` | TWI0: начать обмен, [TWI](#twi) |
| 2 | `int TwiStatus()` | TWI0: состояние обмена, 0 — шина свободна |
| 3 | `void TwiPutByte(data)` | TWI0: байт для записи |
| 4 | `int TwiGetByte()` | TWI0: прочитанный байт |
| 5 | `int NodeStatus()` | 1 — подключён к шлюзу |
| 6 | `int getMilliseconds()` | Время с запуска, мс (переполняется через ~49 суток) |
| 7 | `int getSeconds()` | Время с запуска, с |
| 8 | `int Random()` | Аппаратный генератор, 32 бита |
| 9 | `int NowSeconds()` | Секунды от 00:00:00, местное время, [часы](#часы) |
| 10 | `int Today()` | Дата: `год % 100 << 24 \| месяц << 16 \| день << 8 \| день недели` (1 — понедельник, 7 — воскресенье) |
| 21 | `int UartBytesToRead(port)` | Байт в приёмном буфере — после паузы, [UART](#uart) |
| 22 | `int UartGetByte(port)` | Байт или −1, если буфер пуст |
| 23 | `bool UartPutByte(port, data)` | 1 — принят, 0 — FIFO передачи полно |
| 30 | `void ConfigPin1(pin, mode)` | Настроить пин, [режимы](#режимы-пинов) |
| 31 | `void ConfigPin2(pin, mode, option)` | То же с параметром режима |
| 40–43 | `TwiControl`, `TwiStatus`, `TwiPutByte`, `TwiGetByte` с номером шины первым аргументом | Любая шина: `40 (bus, ctrl)`, `41 (bus)`, `42 (bus, data)`, `43 (bus)` |

Номер 20 (`UartInit` X13 — порт открывает `ConfigPin`) не реализован: вызов неизвестной функции
останавливает программу с `0x88`.

### Часы

Как в X13: время выставляет шлюз. При подключении узел публикует свои часы в предопределённый объект
`0xFF07`. Enviriot записывает туда своё местное время: сразу, если часы узла расходятся с его часами
больше чем на 2 с, и в любом случае раз в час. Запись — 6 байт BCD: секунды, минуты, часы, день,
`день недели << 5 | месяц`, год % 100.

До первой записи и после любого сброса часы идут от 1970-01-01 00:00:00 в момент загрузки: `Today()`
даёт год 70, 1 января, четверг. Enviriot выставляет время сразу после подключения. Системное время
ESP-IDF не меняется: шлюз присылает местное время, а не UTC.

## Ввод-вывод

### Модель

- **Настройка** — в блоке инициализации (первый цикл после старта, адрес 0): `ConfigPin1(pin, mode)`
  или `ConfigPin2(pin, mode, option)` для каждого используемого пина.
- **Ввод-вывод** — в цикле опкодами `IN` (`0xC0`) и `OUT` (`0xC1`). Смысл значения — по режиму пина.
- **Шины** — функциями по номеру шины TWI или порта UART; пины шины настраиваются так же,
  `ConfigPin`, шина создаётся, когда настроены все её пины.

Ввод-вывод сам ничего не публикует: в шину MQTT-SN уходят только мерке́ры, которые зарегистрировал
шлюз.

### Режимы пинов

| 0 | `OFF` | | | |

| 2 | `IN_PU` — с подтяжкой к питанию | дребезг | 0/1 | — |
| 3 | `IN_PD` — с подтяжкой к земле | дребезг | 0/1 | — |
| 4 | `IN_INV_PU` — инверсный с подтяжкой: контакт на землю читается как 1 | дребезг | 0/1 | — |
| 5 | `OUT` | | записанное | 0/1, не 0 — 1 |
| 6 | `OUT_INV` — 1 даёт низкий уровень | | записанное | 0/1 |
| 7 | `OUT_OD` — открытый сток | | записанное | 0/1 |
| 8 | `OUT_OD_INV` | | записанное | 0/1 |
| 9 | `ANALOG` — АЦП | ослабление 0…3 | мВ | — |
| 10 | `DAC` | | записанное | 0…255, больше — 255 |
| 11 | `PWM` | частота, Гц (0 — 1000) | записанное | 0…65535, больше — 65535 |
| 12 | `PWM_INV` | частота | записанное | 0…65535 |

| 14 | `CNT_FALL` — спадов | фильтр | счёт | установить счёт |

| 18 | `TWI1_SDA` | | | |

| 20 | `UART1_TX` | скорость, бод (0 — 9600, до 5000000) | | |
| 21 | `UART1_RX` | формат: биты 0–1 — чётность (0 нет, 1 even, 2 odd), бит 2 — два стоп-бита | | |

| 23–25 | `UART2_TX`, `UART2_RX`, `UART2_DE` | как у UART1 | | |

`ConfigPin1(pin, mode)` — то же, что `ConfigPin2(pin, mode, 0)`.

- Повторная настройка пина тем же режимом и параметром ничего не меняет. Другой режим или параметр
  для уже настроенного пина — ошибка `0x89`: пин сначала освобождают, `ConfigPin1(pin, OFF)`.
- Освобождённый пин — вход без подтяжек.
- **Вход**: дребезг считается по времени при чтении: новое значение `IN` вернёт, когда уровень
  продержался `option` мс. 0 — без фильтра.
- **Выход** после настройки выключен (логический 0). `OUT` с тем же значением, что уже записано, железо
  не трогает. `IN` на выходе возвращает записанное.
- **АЦП** — только ADC1 (GPIO32–39; ADC2 занят WiFi), результат в мВ с калибровкой из eFuse (без неё —
  опорные 1100 мВ). Рабочий диапазон по ослаблению: 0 — 100…950 мВ, 1 (2.5 дБ) — 100…1250 мВ,
  2 (6 дБ) — 150…1750 мВ, 3 (12 дБ) — 150…2450 мВ. Каждый `IN` — одно преобразование.
- **ЦАП** — 8 бит, 0…255 ≈ 0…VDD. Напряжение устанавливается не сразу: читать его АЦП в том же цикле,
  сразу после записи, нельзя — на плате это давало ошибку до 240 мВ; в следующем цикле расхождение
  ЦАП и АЦП — десятки мВ.
- **ШИМ**: 65535 — всегда включён. Частоту задают 4 таймера на все 8 каналов: пины с одной частотой
  делят таймер, пятая разная частота — `0x89`. Разрядность зависит от частоты (до 20 бит); частоты ниже
  100 Гц — от опорных 1 МГц, от 1 Гц.
- **Счётчик** 32-битный, со знаком. `OUT` задаёт текущий счёт (например, 0 — сброс). Где есть
  подтяжки (не GPIO34–39), включается подтяжка к питанию — для открытого коллектора и контактов.
  Фильтр отбрасывает импульсы короче `option` нс.

### Опкоды IN и OUT

`IN <операнд>` кладёт значение пина на стек, `OUT <операнд>` снимает значение со стека и пишет в пин.
Операнд — 4 байта `[place] [type] [base L] [base H]`, как у объектов X13 в компиляторе Enviriot
(`Addr`: `place << 24 | type << 16 | base`). `base` — номер GPIO, `place` и `type` — резерв, прошивка их
не проверяет (компилятору писать 0). `IN`/`OUT` на ненастроенном пине, на пине шины или в режиме без
этой операции — ошибка `0x8A`.

В JS сейчас это переменные с именами тегов X13, объявленные без значения: `var Op2;` — чтение даёт `IN`,
запись `OUT`; число в имени — GPIO. В тестах: `Op`, `Ip` — дискретные, `Pp` — число на выход, `Ae`, `Cp` —
числа на вход. Смысл значения задаёт режим из `ConfigPin`, а не буквы тега; примеры —
[tests/plc](../tests/plc/README.md).

### TWI

Две шины, 0 и 1, на любых пинах с выходом. Включаются внутренние подтяжки, но они слабые — на шине
нужны внешние 2.2–4.7 кОм. Функции — как в X13 (`exttwi.c`): обмен идёт в фоне, цикл не ждёт.

Управляющее слово и статус — 4 байта: `адрес | access << 8 | write << 16 | read << 24`. Адрес — 7 бит,
`write` и `read` — сколько байт записать и затем прочитать (0…32, после повторного START).

| Бит `access` | Значение |
|---|---|
| `0x01` WRITE, `0x02` READ | Есть что записать / прочитать |
| `0x08` BUSY | Обмен идёт |
| `0x10` RDY | Обмен завершён, остальные биты сброшены |
| `0x20` WD | Таймаут: 250 мс от `TwiControl` |
| `0x40` SLANACK | Устройство не ответило (на ESP32 — и NACK на байте данных), `read` = 0 |
| `0x80` ERROR | Ошибка шины |

1. `TwiControl(ctrl)` открывает обмен; пока предыдущий не закрыт, вызов игнорируется. Без записи
   (`write` = 0) обмен начинается сразу; `write` = `read` = 0 — проверка присутствия устройства.
2. `TwiPutByte(data)` — байты для записи; обмен начинается с последним из `write`, лишние игнорируются.
3. `TwiStatus()` — статус; 0 — обмена нет. Статус с WD, SLANACK или ERROR, а также RDY без чтения
   закрывает обмен.
4. `TwiGetByte()` — после RDY по одному `read` байт, последний закрывает обмен; без данных — 0.

Отсутствие устройства — статус, а не остановка программы. `addr` больше 0x7F, `write` или `read` больше
32, функции на ненастроенной шине — ошибка `0x8A`. Если зависший обмен ещё занимает шину после WD,
следующий начнётся, когда она освободится (не позже 200 мс).

### UART

Порты 1 и 2 — номер UART, `port` у функций, — кроме порта линии MQTT-SN (по умолчанию UART1 — тогда
`UART1_*` дают `0x89`). 8 бит данных. Порт открывается, когда настроены TX и RX; DE можно добавить в любой
момент — порт переходит в полудуплекс RS-485, DE держится во время передачи. Функции — как в X13
(`extser.c`), без `UartInit`.

- `UartBytesToRead(port)` сообщает принятые байты после паузы: когда с прошлого вызова не пришло ничего
  нового, то есть кадр закончился (пауза не короче цикла PLC, 10 мс), или когда заполнена половина
  приёмного буфера (256 из 512 байт). Иначе 0. Взятые `UartGetByte` байты новыми не считаются.
- `UartGetByte(port)` — байт или −1.
- `UartPutByte(port, data)` — байт в аппаратное FIFO 128 байт; не ждёт и возвращает 0, когда FIFO
  полно (X13 возвращал позицию в пакете или −1).

### Ошибки

| Код | Когда |
|---|---|
| `0x8A` | Пин не существует или зарезервирован; режим или параметр недопустим для пина; `IN`/`OUT`/шина без настройки; `TwiControl` с адресом больше 0x7F или длиной больше 32; железо отвергло настройку (недостижимая частота и т. п.) |
| `0x89` | Пин уже настроен иначе этой программой; роль пина шины занята другим пином; нет свободного канала или таймера ШИМ, блока счётчика; порт UART занят линией MQTT-SN |
| `0x87` | Не хватает аргументов на стеке |

При остановке по ошибке шлюз получает отчёт `STOP_RESP` с кодом и регистрами VM.

### Перезапуск программы

При `START` (новая программа или та же) и при загрузке устройства настроенные пины помечаются
устаревшими. `ConfigPin` с тем же режимом и параметром снимает пометку и ничего не перенастраивает —
выходы не мигают, шины не пересоздаются. Если новой программе нужен ресурс устаревшего пина (канал ШИМ,
блок счётчика, роль пина шины), устаревший пин освобождается сразу. После первого успешного цикла
освобождаются пины, которые новая программа не настроила.

`STOP` и остановка по ошибке оставляют выходы как есть.

## Float

32-битный IEEE-754 в той же ячейке стека, что и целое. Все команды однобайтовые, порядок операндов
как у целых (`a b FSUB` → `a - b`, `a b FCGT` → `a > b`). Результаты — как в JavaScript, исходном
языке программ.

| Код | Команда | Результат |
|---|---|---|
| 0x18–0x1B | `FADD FSUB FMUL FDIV` | float; деление на 0 даёт ±Infinity/NaN без ошибки |
| 0x1C, 0x1D | `FNEG FABS` | float |
| 0x1E, 0x1F | `FMIN FMAX` | `Math.min/max`: NaN, если любой операнд NaN; −0 < +0 |
| 0x28–0x2D | `FCEQ FCNE FCGT FCGE FCLT FCLE` | 0/1; сравнение с NaN — 0, кроме `FCNE` |
| 0x2E | `FCZE` | 1, если ±0 |
| 0x2F, 0x36, 0x37 | `FISFINITE FISNAN FISINF` | 0/1 |
| 0x30, 0x31 | `S32TOF U32TOF` | float из int32 / uint32, округление к ближайшему |
| 0x32, 0x33 | `FTOS32 FTOU32` | `x \| 0`, `x >>> 0`: отбрасывание дробной части, по модулю 2³², NaN и ±Infinity — 0 |
| 0x34 | `FROUND` | `Math.round`: половина к +Infinity (−2.5 → −2), float |
| 0x35 | `FTRUNC` | `Math.trunc`, float |

`FTOS32` и `FTOU32` дают одни и те же 32 бита и отличаются только тем, как компилятор трактует
результат дальше.

## Переменные (мерке́ры)

Шлюз регистрирует переменные программы тегами `M<тип><индекс>`; индекс — в единицах типа от начала RAM.

| Тег | Тип | В сообщении |
|---|---|---|
| `Mz` | bool | 1 байт |
| `Mb`, `MB` | int8, uint8 | 1 байт / упакованное целое |
| `Mw`, `MW` | int16, uint16 | упакованное целое |
| `Md` | int32 | упакованное целое |
| `Mf` | float | 4 байта IEEE-754 LE, без упаковки, адресуется словами как `Md` |

## Память

| | По умолчанию | Kconfig |
|---|---|---|
| Программа | 16 КБ (раздел `plc` 64 КБ) | `PLC_PROGRAM_SIZE`, до 64 КБ |
| Данные (глобальные, стек) | 1024 слова | `PLC_RAM_WORDS` |
| Мерке́ры, доступные шлюзу | первые 256 слов | `PLC_RW_WORDS` |

Программа хранится во flash-разделе `plc` и записывается при `START` (только изменённые сектора 4 КБ),
дно стека — в NVS.

## Отличия от X13 на STM32

- `%` на 0 останавливает программу с `0x86`, как и `/` (STM32 возвращал делимое).
- Сдвиги на 32 и больше дают 0 (`ASR` — знак), `INT_MIN / -1` = `INT_MIN` — как на ARM.
- `CALL` при пустом стеке (`SP = 0`) — ошибка `0x87` (на STM32 запись за пределы RAM).
- `IN`/`OUT` адресуют GPIO, а не объекты X13 (`Iz12`, `Op5`); объектов ввода-вывода в словаре нет.
- TWI — только из программы, объекта `Ta0` нет; вторая шина — функциями 40–43. `TwiControl` проверяет
  длины (X13 писал за пределы буфера).
- Часы — не аппаратный RTC с резервным питанием: после сброса они идут с 1970-01-01, пока шлюз не
  выставит время.
- UART: `port` — номер UART ESP32, порт открывает `ConfigPin` вместо `UartInit` (20);
  `UartPutByte` возвращает 1/0.
