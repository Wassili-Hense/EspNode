# Раздел `cfg`: формат v1

Конфигурация узла, которую страница установки (GitHub Pages) записывает при прошивке: интерфейсы,
их параметры, имя и адрес узла. Прошивка раздел только читает. Одна прошивка подходит для всех
устройств; значения Kconfig используются, только если `cfg` нет или он испорчен.

> Статус: прошивка читает `cfg` (`components/node_cfg`), но запускает пока только один интерфейс UART
> с кадром SLIP. `cfg` с WiFi, кадром RS-485 или несколькими интерфейсами применяется как испорченный.
> Образ для разработки собирает `tools/mkcfg.py`; страница установки ещё не готова.

## Разметка flash (4 МБ)

| Раздел | Тип / подтип | Адрес | Размер | Кто пишет |
|---|---|---|---|---|
| — (загрузчик) | | 0x1000 | | прошивка |
| — (таблица разделов) | | 0x8000 | 3 КБ | прошивка |
| `nvs` | data / nvs | 0x9000 | 24 КБ | узел: адрес от DHCP, имя, объекты OD, дно стека PLC |
| `phy_init` | data / phy | 0xF000 | 4 КБ | узел |
| `factory` | app / factory | 0x10000 | 1.5 МБ | прошивка |
| `plc` | data / 0x40 | 0x190000 | 64 КБ | узел: программа PLC |
| `cfg` | data / 0x41 | 0x1A0000 | 4 КБ | **страница установки** |
| свободно | | 0x1A1000 | ~2.4 МБ | |

Адреса после выпуска устройств не меняются: таблица разделов перезаписывается только прошивкой по USB.

## Формат

Все числа little-endian, строки UTF-8 без завершающего нуля, IPv4 — байты в порядке записи
(192.168.1.10 → `C0 A8 01 0A`).

### Заголовок, 16 байт

| Смещение | Размер | Поле | Значение |
|---|---|---|---|
| 0 | 4 | magic | `ECFG` (`45 43 46 47`) |
| 4 | 1 | version | 1 |
| 5 | 1 | reserved | 0 |
| 6 | 2 | length | длина записей N, байт (не больше 4080) |
| 8 | 4 | generation | номер конфигурации, новый при каждой записи `cfg`: время генерации в секундах Unix |
| 12 | 4 | crc | CRC-32 байтов 0–11 заголовка и N байтов записей |

После записей до конца раздела — `FF`.

CRC-32 — как в zlib / IEEE 802.3: полином `0x04C11DB7` (отражённый `0xEDB88320`), начальное значение
`0xFFFFFFFF`, итоговый XOR `0xFFFFFFFF`; `"123456789"` → `0xCBF43926`.

`version` меняется только при несовместимом изменении. Новые типы записей версию не меняют: прошивка
пропускает незнакомые записи.

### Записи

`[type: 1 байт] [len: 1 байт] [value: len байт]`, подряд, без выравнивания.

| type | Запись | len | Значение |
|---|---|---|---|
| `0x01` | NODE_NAME | 1–23 | Имя узла (ClientId MQTT-SN) |
| `0x02` | NODE_ADDR | 1 | Адрес узла на serial / RS-485; `FF` — получить по DHCP |
| `0x10` | IF_UART | 9 | Интерфейс UART: `port` u8 (0–2), `tx` u8, `rx` u8, `de` u8 (`FF` — нет), `baud` u32, `framing` u8: 0 — X13 serial (SLIP), 1 — X13 RS-485 (`F0 1C`) |
| `0x20` | IF_WIFI | 0 | Интерфейс WiFi, параметры — записи `0x21`–`0x24` |
| `0x21` | WIFI_SSID | 1–32 | |
| `0x22` | WIFI_PASSWORD | 0–64 | Открытым текстом; пустой — открытая сеть |
| `0x23` | WIFI_IP | 12 | `ip[4]`, `mask[4]`, `gateway[4]`; нет записи — DHCP |
| `0x24` | MQTTSN_GATEWAY | 6 | `ip[4]`, `port` u16; нет записи — поиск шлюза широковещательным SEARCHGW |

Интерфейсы — записи `IF_UART` и `IF_WIFI` по порядку. Первый — клиент: через него узел подключается к
своему шлюзу MQTT-SN. Следующие — шлюз (брокер): узлы X13 на них работают через этот узел, сообщения
упаковываются в FORWARD. Одиночные записи при повторе берутся последние.

### Пример

Узел `kitchen`, адрес по DHCP, UART1 (TX 17, RX 16, без DE), 38400, кадр SLIP, generation `0x6708F000`:

```
0000: 45 43 46 47 01 00 17 00 00 F0 08 67 4C 79 26 E2
0010: 01 07 6B 69 74 63 68 65 6E 02 01 FF 10 09 01 11
0020: 10 FF 00 96 00 00 00
```

length = 23 (`0x17`), crc = `0xE226794C`.

На этом примере проверяются разбор в прошивке (`test/host/test_cfg.c`) и генератор `tools/mkcfg.py`.

## Как прошивка применяет `cfg`

1. При старте проверяет magic, version и CRC. Если `cfg` нет, он испорчен или версия незнакома, — значения по
   умолчанию (Kconfig: UART0, TX 1, RX 3, 38400, SLIP — плата подключается к Enviriot по USB) и сообщение
   в журнал. Консоли ESP-IDF и журнала загрузчика на UART0 нет, остаются только сообщения ROM при сбросе.
2. Недопустимые параметры — то же, что испорченный `cfg`: узел должен остаться доступным. Недопустимыми считаются:
   - пин, которого нет или который занят flash (GPIO6–11) либо консолью отладочной сборки;
   - TX или DE на пине только для входа (GPIO34–39);
   - один пин у двух ролей или интерфейсов, повтор порта, порт консоли;
   - скорость вне 1200–5000000, незнакомый кадр, адрес узла 0;
   - WiFi без SSID или два WiFi.

   Так же обрабатывается то, что прошивка ещё не умеет (см. статус).
3. Настройки, изменённые по сети объектами OD (имя, адрес узла, адрес шлюза), хранятся в NVS и главнее `cfg`.
   Прошивка помнит `generation` последнего применённого `cfg` (ключ NVS `cfg_gen`); новое значение сбрасывает
   эти правки, иначе они перекрыли бы новую конфигурацию, записанную со страницы установки. Список объектов
   OD и программа PLC при этом сохраняются. Если `cfg` нет, сохранённые значения не трогаются.
4. Пароль WiFi драйверу передаётся с `WIFI_STORAGE_RAM`: копия в NVS драйвера не создаётся.
5. Тип устройства (`0xFFC0`) составляется из интерфейсов по порядку:
   - `E1` (ESP32);
   - буква на каждый интерфейс, как PHY в X13: UART с кадром SLIP — `S`, с кадром RS-485 — `M`, WiFi — `W`;
   - версия железа `10`.

   Получается `E1S10`, `E1W10`, `E1WM10`. Буквы PHY не входят в признак сброса настроек узла: смена шаблона
   сбрасывает только то же, что новое `generation`.
6. Пины и порты интерфейсов недоступны программе PLC.
